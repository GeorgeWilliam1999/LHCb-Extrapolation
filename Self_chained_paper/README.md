# LHCb self-chained extrapolation paper

Overleaf-ready LaTeX source for the second mini-paper of the extrapolation
programme: one network of a fixed step in $z$, applied to its own output $N$
times across the LHCb magnet, trained without labels, and trained a second time
with a loss weighted by what an error at each step costs at the endpoint. Built
in the same mould as the first mini-paper (`Mini_paper/`): same document class,
same packages, same figure and table conventions.

**`main.tex` is the authoritative source**, and it is the only one. It is a
single self-contained file; the per-section drafts it was assembled from have
been deleted, so no second copy of the body text exists. **Edit `main.tex`.**

Every number in the paper traces to a committed file in this repository. The two
maps below give it, and they are the same rows as Appendix A of the paper.

## Build

```sh
sh build.sh          # pdflatex, bibtex, pdflatex, pdflatex
make                 # the same thing
make zip             # rebuilds Self_chained_paper.zip
```

Requires `pdflatex` and `bibtex` only. No exotic packages: geometry, amsmath,
amssymb, graphicx, booktabs, caption, natbib, xcolor, hyperref.

To regenerate the numbers and the figures first, from inside this folder:

```sh
PYTHONNOUSERSITE=1 /data/bfys/gscriven/conda/envs/TE/bin/python scripts/numbers.py
PYTHONNOUSERSITE=1 /data/bfys/gscriven/conda/envs/TE/bin/python scripts/fig01_crossing.py
#   ... and so on through scripts/fig17_loss_weights_schematic.py
```

`numbers.py` reads every experiment folder read-only and writes
`results/paper_numbers.json`, the `results/tab_*.csv` tables and the
`results/cache/` arrays. Each figure script writes one PNG into `figures/` and
one companion `results/fig*.csv`.

## Conventions of this paper

These are binding on the prose, the tables, the figures and the scripts.

1. **Slopes are dimensionless.** $t_x$ and $t_y$ are $dx/dz$ and $dy/dz$ and
   are quoted as dimensionless numbers in scientific notation. There is no
   $\times 10^{3}$ scaling and the word "mrad" appears nowhere -- not in the
   text, not in a table, not on a figure axis, and not in the slope paths of
   any script. Some earlier result files label a $\times 10^{3}$ slope as
   "mrad"; this paper does not, and any script reading those files strips the
   scaling and the label.
2. **Momentum bands.** The bands are $<3$, 3--8, 8--20, 20--50 and $>50$ GeV.
   Where relevant the 10--50 GeV loss window is reported as an extra row. The
   track count per band is always shown. The $>50$ band is thin: 30 test
   tracks, and it is read accordingly.
3. **Figures come from committed results.** Every figure is regenerated by a
   script in `scripts/` from committed files in `results/` only. No figure is
   copied in from an experiment folder.
4. **No experiment code-words in the prose.** Block letters, folder names and
   cluster identifiers appear only in Appendix A. In the body, networks are
   named by their step count $N$, their stage count $q$ and their step length
   $\Delta z$.
5. **Which runs the comparison uses.** The pooled-loss comparison uses the runs
   extended to their own plateau, not the stopped snapshot of 18 September
   2026. The one exception is the grid table over step counts and stage counts,
   which uses the snapshot and says so in its caption.

## Discrepancies found while writing, and what was corrected at source

Every number in the paper was recomputed from the committed result files by
`scripts/numbers.py` rather than copied from an experiment README or write-up.
That caught the following disagreements. Nothing in an experiment folder was
edited: the result files were right in every case, and the correction is in the
paper.

| what the earlier record says | what the committed file says | where corrected |
|---|---|---|
| (a) the reweighted-loss write-up gives the lever arm's maximum at N = 64 as 5,258.7 mm | `results/tab_loss_constants.csv` records the same `lever_max_mm` = 5258.703125, but that is L + dz, the value of Eq. (14) at c = 0, and no output of the scheme sits at c = 0. The largest lever arm the loss actually weighs is at the first Gauss node of the first step, L + dz(1 - c1) = 5177.8 + 80.903 x (1 - 0.21132) = **5,241.6 mm** | not corrected in the paper. Section 2.6 and the Figure 7 caption quote 5,258.7 mm, which is the module's own reported range and is what the drawn curve is anchored on; Sections 7-9 quote no lever-arm maximum. The two sides disagree about which endpoint of the range is meaningful, not about the arithmetic, so both are recorded here rather than one being silently changed |
| (b) the pre-flight record gives the cost-weighted loss a 57.8 % share of the 10-50 GeV window | 47.0 % on the extended network, which is what the paper uses. The 57.8 % was measured on the stopped checkpoint of 18 September 2026; the weights are identical and the residuals are not | Section 5.2 footnote, Table 13 and Section 7.3; the paper states the extended value and says the stored record is larger |
| (c) "the systematic under-bend is removed" | it holds at N = 64 only. The pooled-loss in-window signed median in x is -54 um at N = 64, +18 um at N = 128 and +30 um at N = 256, so there is no common under-bend across the three | Section 5.5 and Section 7.1: the claim is narrowed to "the absolute in-window offset falls in all three pairs, and falls relative to the error's own size in two of the three" |
| (d) the second pre-registered criterion is presented as distinguishing the two losses | the extended pooled-loss counterpart has itself fallen to 1.30e-6, below the 1.6e-6 threshold, so both losses clear it | Section 5.4 and Section 7.1: the second condition is reported as met and as the weaker of the two |
| (e) "worse below the crossover in six of six, more coherent in five of six" | worse below the crossover in **five** of six (3-8 GeV at N = 256 is 13 % better), and more coherent in **six** of six | Sections 5.4, 5.7 and 7.2 |
| (f) the three extended pooled runs' `record.json` reports 51, 64 and 43 rounds | the stored round counter skips exactly one number where each run was picked up and extended, so the distinct round counts are 50, 63 and 42 | Table 15, Table 26 and Appendix A quote the distinct counts |
| (g) the duplicate-job note is stated as "302 / 13 duplicated rows" | 302 restart numbers and 13 round numbers are duplicated, but de-duplication drops 307 history rows (1,807 - 1,500) and 14 round rows (74 - 60), because some numbers repeat more than once | Section 5.10 states the duplicated *numbers* and the distinct counts separately |
| (h) the q = 2 ceiling at N = 128 is described as "below a quarter of a micrometre" | 0.511 um, which is the largest of the three sub-micrometre q = 2 ceilings and is worse than the N = 64 and N = 256 cells | Section 4.2 and Table 6 |
| (i) the network-to-ceiling gap at N = 2 is quoted as 10^3 to 10^6 | at N = 2 the three cells above q = 2 sit within a factor of **1.5 to 43** of their own ceilings; the 360 to 1.4e6 range belongs to the N >= 64 rows | Section 4.2 |
| (j) `Mini_paper/README.md` (paper 1) says its bibliography has 12 entries | `Mini_paper/references.bib` holds 11 | recorded here; paper 1's README is not edited by this paper |

## Scope note

This paper covers the single-network-chained design from 16 September 2026
onward -- one network of step $\Delta z$ applied $N$ times across the magnet,
under the pooled loss and under the cost-weighted loss -- together with the
study of the reference schemes against the Geant4-true state. The earlier
multi-network work, in which a separate network was trained for each leg, is
paper 1 (`Mini_paper/`) and is not repeated here.
