## Decisions and dead ends

- **The other study's comparator row is dropped, the exact scheme is kept.** The imported
  in-depth study and table script both read a folder that holds two things: the exact q-stage
  scheme's end states (a numerical-scheme comparator, legitimate) and another block's trained
  chains (a comparison against other networks, which George ruled out for a block in isolation).
  Pointing that constant at a view holding only the first keeps one and drops the other without
  editing or touching anything. Pointing it at nothing would have dropped the exact scheme too,
  because the E2 folder only has it at N = 2 and N = 256.
- **Relabelling has to cover `print` as well as the titles.** F3's runner only wraps the
  matplotlib titles, which is enough when the replacement is another two words; here one printed
  table header carried a block letter, so the built-in `print` is wrapped too, and the produced
  CSV headers and cells are rewritten afterwards. The rewriting is guarded so a second run over
  the same folder does not double it.
- **Two bugs found and fixed in my own code while smoke-testing.** (1) The printed table looked
  up its row by `p_lo` alone, so the new 5-8 GeV band printed the 5-7 GeV numbers (the CSV was
  right); now it matches on both edges. (2) F3's runner calls the imported `main()` with no
  arguments, so the three E3 scripts that parse their own command line choked on the runner's
  flags — never noticed before because only `convergence` had ever been run through it
  (`F3_Analysis/results/run_log.json` has one entry). The runner now passes an empty argument
  list to any `main` that takes one, and `--case N,q` passes a network through.
- **Importing a script out of a read-only folder writes a `.pyc` into it.** Three appeared in
  `F2_Analysis/__pycache__` before I noticed (their sources had changed today, so the cached
  copies were stale). Every G2/G3 script now sets `sys.dont_write_bytecode = True` before
  importing anything from Block E or Block F, and a re-run of the whole set left nothing new
  under either. The three already written were left alone (deleting nothing outside the
  scratchpad); they are bytecode, not content, and F3's runner has been doing the same since
  2026-09-20.
- **Open, inherited, not fixed:** `figures/error_qdz.png` lays itself out over the full N x q
  grid and is mostly empty for three runs on a diagonal; the imported convergence reader counts
  rows rather than distinct rounds, so for a double-written run its round count is inflated
  (G2's convergence script is the one to read); the in-depth study picks the network with the
  best validation mean, which can be a run still training. All three are in the G3 README.
