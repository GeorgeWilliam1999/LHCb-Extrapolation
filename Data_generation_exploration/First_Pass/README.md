# First Pass — generating and understanding one full simulated LHCb event

Goal: run the official LHCb simulation locally (Nikhef, CVMFS releases only — no
grid needed), produce full simulated events, read the MC truth back, and
visualise/understand one event. This is the entry point of the data-generation
exploration for applying the Raissi discrete-time approach to the LHCb
extrapolator: eventually we want simulated events whose truth (MCParticles +
MCHits) trains and validates extrapolator networks inside the real detector.

## The simulation chain (where this fits)

```
Gauss (v61 = Gauss-on-Gaussino)      <- THIS FOLDER: pp collisions (Pythia8)
  |  .sim  (MC truth: MCParticles, MCVertices, MCHits)   + decays (EvtGen)
  v                                                      + detector transport (Geant4)
Boole                                <- digitisation: MCHits -> simulated raw banks
  |  .digi (what the detector electronics would output)
  v
Moore / HLT1+HLT2                    <- trigger + reconstruction (Allen = GPU HLT1)
  |  .dst
  v
DaVinci                              <- physics analysis
```

HLT1/HLT2 do not generate anything: they select and reconstruct. Simulation of
"what the detector saw" is entirely Gauss (+ Boole for electronics response).

## Environment

- Everything comes from `/cvmfs/lhcb.cern.ch`. Source [env.sh](env.sh) to get `lb-run`.
  An active conda env breaks Gaudi jobs (PYTHONPATH leak) — env.sh handles that.
- Gauss v61r0p2 (newest release on CVMFS, July 2026) = **Gauss-on-Gaussino**,
  the Run 3+ simulation: Gaussino 2.0 core, Gaudi 40.3, LHCb 59.0, Detector 3.10
  (DD4hep geometry), Geant4 10.7. Native el9 build, runs directly on this node.
- Its Sphinx docs ship on CVMFS:
  `/cvmfs/lhcb.cern.ch/lib/lhcb/GAUSS/GAUSS_v61r0p2/docs/` — see
  `getting_started/first_simulation_job.md` and `examples/run3.md` (the recipe
  used here).
- Data packages pulled via `lb-run --use`: **AppConfig v4r8** (beam-condition
  options; the v3rX series is classic-Gauss-only and fails on v61) and
  **Gen/DecFiles v33r3** (event types + decay tables).

## Usage

```bash
cd First_Pass
bash run_gauss.sh                          # 1 event  -> run_output/GaussDev-...sim
bash run_gauss.sh override_five_events.py  # 5 events -> run_output/GaussDev5-...sim

```

## What one "event" is

One event = one LHC **bunch crossing** at the 2024 running conditions
(6.8 TeV per beam, nu = 7.6 mean total pp interactions per crossing, drawn
Poisson >= 1 by the `FixedLuminosityWithSvc` pile-up tool). Each interaction is
generated by Pythia8 (minimum bias = all soft QCD, *including elastic*),
hadron decays by EvtGen, then all stable particles are transported through the
DD4hep detector geometry by Geant4, which records **MCHits** (entry/exit point,
energy deposit, time, owning particle) in each sensitive detector
(VP, UT, FT, Rich, Ecal, Hcal, Muon).

The .sim file stores everything **packed** (`pSim/...` containers);
`GaudiConf.SimConf(EnableUnpack=True)` + Data-On-Demand unpacks transparently
to `MC/Particles`, `MC/Vertices`, `MC/<det>/Hits` on access.

Random seeds derive from (RunNumber, EventNumber), so any event is exactly
reproducible: event 1 of the 5-event run is bit-identical to the 1-event run.

## The figures (figures5/, event index 1 of the 5-event file)

- `event_display.png` — x-z and y-z views of the whole detector. MC hits as
  coloured marks (VP blue / UT green / FT magenta / Muon yellow), thin grey
  lines connect the hits belonging to one particle. **The dipole signature is
  directly visible**: tracks kink in x-z between UT and the SciFi stations but
  run straight in y-z (the magnet bends only horizontally). The three SciFi
  station groups (T1-T3) resolve clearly at z = 7.9-9.5 m.
- `vertex_zoom.png` — the interaction region: 7 pile-up primary vertices spread
  over |z| < 50 mm, VP hits showing the VELO module positions along z,
  secondary vertices from decays and material interactions.
- `generator_summary.png` — per-collision charged multiplicity (a few busy
  non-diffractive collisions dominate; elastic/diffractive ones are nearly
  empty), momentum spectrum (peaks at a few hundred MeV, tail to the beam
  energy), and pseudorapidity (backward hemisphere is uninstrumented; the
  2 < eta < 5 band is what LHCb sees).

Event 1 statistics: 7 pp collisions, 2689 MCParticles (1258 charged),
3222 MCVertices, 591 VP + 283 UT + 1013 FT + 9 Muon MCHits.

### Note: the first event of run 1 is a ~0.1% outlier

The very first event with `RunNumber=1` draws **one** interaction for the
crossing (P ~ 0.4% at nu = 7.6) and it is **elastic** pp -> pp (~22% of the
total cross-section): 2 MC particles (the scattered beam protons, pz = +-6.8 TeV),
one primary vertex, **zero** detector hits — the protons stay in the beam pipe.
A useful lesson (minbias includes invisible events; file size 18 kB) but not a
representative crossing; use a busier event from the 5-event file for display.
